# Лабораторная работа №1 — shell-скрипты

Среда: Linux, Bash 4.4+, Git, GNU coreutils, grep, awk, util-linux (`flock`),
файловая система `/proc`. Подходит Ubuntu, в том числе WSL.
Запускайте команды из корня репозитория. Права root не требуются.

## 1. Сравнение веток

```bash
bash lab1/branch_diff.sh https://github.com/example/project.git main develop
```

Три обязательных аргумента: URL репозитория, первая и вторая ветка.
Для приватного репозитория Git должен быть заранее авторизован.
Временный bare-репозиторий удаляется после завершения, рабочие файлы не меняются.
Сравниваются конечные состояния веток в направлении от первой ко второй.

В текущем каталоге создается `diff_report_main_vs_develop.txt`: репозиторий,
ветки, локальная дата и время, список файлов и статистика A/M/D/прочие.
Использован шаблон `diff_report_<BRANCH_1>_vs_<BRANCH_2>.txt` из задания.
Символы, небезопасные для имени файла, кодируются: `feature/test` → `feature%2Ftest`.
Необычные имена файлов в списке экранируются по правилам Bash (`printf %q`).
Переименование считается удалением старого и добавлением нового файла;
изменение типа файла отражается статусом T. Повторный запуск перезаписывает отчет.

## 2. Мониторинг системы

```bash
bash lab1/system_monitor.sh START
bash lab1/system_monitor.sh STATUS
bash lab1/system_monitor.sh STOP
```

Принимается **один** аргумент: START, STOP или STATUS.
START запускает фоновый процесс через `nohup` и печатает PID.
Повторный START сообщает существующий PID. Блокировки `flock` защищают
в том числе от одновременных запусков. STOP проверяет принадлежность PID
этому скрипту и отправляет SIGTERM; STATUS сообщает, запущен ли монитор.
Обычный STOP завершает также ожидание следующего измерения.

Первое измерение производится сразу (замер CPU занимает одну секунду),
последующие — каждые 600 секунд. В каталоге, из которого выполнен START,
создается ежедневный `system_report_YYYY-MM-DD.csv` с заголовком:

```text
timestamp;all_memory;free_memory;%memory_used;%cpu_used;%disk_used;load_average_1m
```

- `timestamp`: локальное время `YYYY-MM-DD HH:MM:SS`.
- `all_memory`, `free_memory`: MemTotal и MemFree из `/proc/meminfo`, в КиБ.
- `%memory_used`: `(MemTotal - MemFree) / MemTotal * 100`; включает кеши.
- `%cpu_used`: средняя загрузка всех CPU за одну секунду по разности
  счетчиков `/proc/stat`; idle и iowait считаются простоем.
- `%disk_used`: процент использования `/` по `df -P`.
- `load_average_1m`: первое поле `/proc/loadavg`.

Дробные значения используют точку. При смене даты выбирается новый файл;
при перезапуске строки добавляются, заголовок не повторяется.
Состояние и диагностический `monitor.log` находятся в
`${XDG_STATE_HOME:-$HOME/.local/state}/lab1-monitor/<идентификатор пути скрипта>/`.
Команды управления следует выполнять от того же пользователя и с тем же
XDG_STATE_HOME. Не удаляйте файлы блокировки работающего монитора.

Для проверки можно задать интервал и существующий каталог отчетов:

```bash
MONITOR_INTERVAL_SECONDS=2 MONITOR_REPORT_DIR=/tmp bash lab1/system_monitor.sh START
bash lab1/system_monitor.sh STOP
```

По умолчанию интервал всегда 600 секунд. Один экземпляр допускается
для одного пути скрипта и пользователя. Не запускайте разные копии скрипта
с общим каталогом отчетов.

## 3. Поиск в логах

```bash
bash lab1/log_errors.sh /var/log/example.log ERROR
```

Два обязательных аргумента: читаемый файл и непустое ключевое слово
без перевода строки. Поиск буквальный, чувствительный к регистру.
Считаются **строки**, содержащие слово: несколько совпадений в одной
строке дают одну найденную строку.

В текущем каталоге создается уникальный `log_report.XXXXXX/` с двумя файлами:

- `errors.txt` — найденные строки;
- `count.txt` — количество найденных строк (также выводится в терминал).

При отсутствии совпадений получаются пустой `errors.txt` и счетчик 0.
Исходный лог и предыдущие результаты сохраняются.

Неправильные аргументы и ошибки выполнения завершают скрипты с ненулевым
кодом. Отсутствие различий, совпадений или запущенного монитора не считается ошибкой.
